# MVP Q-Scope: бриф, интервью, адаптивная анкета и приоритизация по брифу

> Углубление MVP: как из задачи клиента получить **вердикт о применимости кванта + сценарий решения +
> оценку эффекта**, двумя путями — через структурированный бриф (с аналитиком) и без брифа, через
> адаптивную анкету-чатбот («Акинатор»). Оба пути ведут в один **движок приоритизации** и один формат
> выхода. Эффект всегда подаётся как оценка «по аналогии», без гарантий.

---

## 0. Архитектура MVP: два входа — один движок — один выход

```
        ВХОД                          ДВИЖОК                         ВЫХОД
┌───────────────────────┐   ┌──────────────────────────┐   ┌───────────────────────────┐
│ A. Гайдед-бриф         │   │ 1. Gate-фильтры (3)       │   │ • Вердикт пригодности      │
│   (с аналитиком,       │──▶│ 2. Классиф. архетипа     │──▶│ • Сценарий решения         │
│    зовём профильные    │   │ 3. Взвешенный скоринг    │   │ • Оценка эффекта (вилка)   │
│    службы)             │   │ 4. Матрица 2×2 → приоритет│  │ • Кого позвать / next step │
│ B. Анкета «Акинатор»   │   │                          │   │ • Бриф для экспертов (PDF) │
│   (self-service, без   │──▶│   (одна и та же логика)   │   │                           │
│    брифа, от общего    │   │                          │   │                           │
│    к частному)         │   └──────────────────────────┘   └───────────────────────────┘
└───────────────────────┘
```

- **A. Гайдед-бриф** — для клиента, который готов подготовиться и собрать команду. Сервис выдаёт шаблон
  брифа + список вопросов по ролям → клиент проводит внутреннее интервью → загружает бриф → получает
  вердикт.
- **B. Анкета «Акинатор»** — для клиента, который пришёл «с улицы» и ничего не готовил. Чат-бот сам ведёт
  от общих вопросов к частным, ветвится по ответам и в конце **сам строит мини-бриф** + показывает сценарий.

Принцип: **анкета — это тот же бриф, но собранный машиной по шагам.** Поля брифа = целевые слоты,
которые анкета постепенно заполняет вопросами.

## 1. Движок приоритизации по брифу (ядро)

Та же логика, что в исследовании (`Исследование-...md`, разд. 3.4), но привязанная к полям брифа.

### 1.1. Шаг 1 — Gate-фильтры (любое «нет» → не квантовый кейс сейчас)
| Фильтр | Что проверяем | Поле брифа / вопрос анкеты |
|---|---|---|
| **G1. Классика провисает** | текущий метод не тянет по времени/качеству или растёт экспоненциально/NP-трудно | «Текущее решение и боль», «время при росте объёма» |
| **G2. Формализуемость** | есть чёткая целевая функция + переменные + ограничения (→ QUBO/Hamiltonian) | «Цель/метрика», «что можем менять», «ограничения» |
| **G3. Нет I/O-bottleneck** | вход данных мал относительно пространства решений | «Объём входных данных» |

Если фильтр не пройден → выход-вердикт **«Классического/гибридного решения достаточно»** или
**«Пока не для кванта»** с объяснением причины (а не просто «нет»).

### 1.2. Шаг 2 — Классификация архетипа
По ответу «что по сути нужно сделать» → один из 4 архетипов: **оптимизация · симуляция · сэмплинг · ML/QML**
(см. дерево анкеты, разд. 4). Архетип определяет вес «fit» и библиотеку сценариев.

### 1.3. Шаг 3 — Взвешенный скоринг (0–5 по критерию)
| Критерий | Вес | Откуда берём из брифа |
|---|---|---|
| Бизнес-ценность / ROI / размер эффекта | 25% | экономика, метрика, частота |
| Классическая твёрдость + вероятность реального speedup | 25% | боль текущего метода, рост времени |
| Архетип-fit (симуляция/оптимизация ≫ QML) | 15% | тип задачи |
| Реализуемость на горизонте (NISQ-сейчас vs FT-позже) | 15% | размер задачи, архетип |
| Готовность данных/инфраструктуры/команды | 10% | секция «готовность» |
| Допустимость приближённого решения | 10% | «нужен ли строгий оптимум» |

### 1.4. Шаг 4 — Матрица 2×2 и приоритет
Оси: **Quantum advantage potential** (твёрдость + speedup + архетип) × **Business value / feasibility**.
- ↗ **PoC сейчас** (высокий потенциал + высокая ценность) — приоритет 1.
- ↖ **Watchlist / glide path** (потенциал есть, ценность/реализуемость низкая) — приоритет 3.
- ↘ **Классический / гибридный солвер** (ценность есть, потенциала нет) — квант не нужен.
- ↙ **Отбросить**.

## 2. Шаблон брифа клиента (12 секций)

Одностраничный структурированный бриф. Заполняется клиентом (сам или с аналитиком) и идёт экспертам.

1. **Владелец задачи и роли** — кто владелец процесса, кто принимает решение, кто бюджетодержатель.
2. **Бизнес-задача в одном предложении** — «как есть» → «как надо».
3. **Текущее решение и боль** — как решается сейчас (вручную/Excel/эвристика/солвер); что не устраивает
   (время, стоимость, качество, масштаб).
4. **Тип задачи / цель** — что оптимизируем/прогнозируем/моделируем; что значит «лучше».
5. **Переменные решения** — что в принципе можно менять (назначения, маршруты, доли, параметры).
6. **Ограничения** — жёсткие (нельзя нарушать) и мягкие (желательно); примеры.
7. **Масштаб** — сколько объектов/переменных одновременно; как растёт со временем.
8. **Данные** — какие нужны, объём, формат, где лежат, доступность, чувствительность.
9. **Метрика успеха и базовая линия** — как меряем эффект; текущее значение; целевое.
10. **Частота и режим** — разовая/регулярная; нужен ли real-time.
11. **Экономика** — стоимость текущего решения; цена ошибки; ожидаемый эффект от улучшения на X%.
12. **Готовность и ограничения** — данные/ИТ/команда/бюджет/сроки; комплаенс, безопасность данных.

> Поля 3–7, 9 закрывают **gate-фильтры и архетип**; поля 11, 10 — **бизнес-ценность**; поле 12 — **готовность**.

## 3. Вопросы для интервью по ролям (кого позвать и что подготовить)

Сервис выдаёт клиенту этот список, чтобы он **пригласил профильные службы** и пришёл подготовленным.

### Бизнес-заказчик / владелец процесса
- Какую бизнес-боль решаем и почему сейчас? Что меняется, если не решить?
- Как поймём, что стало лучше? Какая метрика и её текущее значение?
- Какой эффект считаем успехом (в деньгах/времени/качестве)?

### Профильное подразделение / операции
- Как процесс устроен пошагово сегодня? Кто и чем решает задачу?
- Что можно менять (переменные) и что нельзя (жёсткие ограничения)?
- Сколько объектов в задаче и как часто она возникает? Пики?

### Владелец данных / аналитика
- Какие данные описывают задачу? Объём, структура, качество, история?
- Насколько они доступны и актуальны? Есть ли разметка/целевая переменная?

### ИТ / инфраструктура
- Где живут данные и системы? Какие интеграции и ограничения?
- Требования к безопасности, развёртыванию, SLA, real-time?

### Финансы
- Сколько стоит текущее решение (труд, простои, потери)? Цена ошибки?
- Какая рамка ROI и порог окупаемости для пилота?

### (опц.) Комплаенс / безопасность
- Регуляторные ограничения, требования к данным, аудит.

## 4. Адаптивная анкета «Акинатор» (self-service, без брифа)

### 4.1. Принципы
- **От общего к частному, ветвление по ответам** (progressive disclosure / decision tree).
- **Закрытые ответы** (как у MS/AWS) → детерминированный маппинг ответ → слот брифа + баллы.
- Каждый ответ обновляет **профиль задачи** и шкалы скоринга; ненужные ветки не показываются.
- 8–15 вопросов до результата (зависит от ветки). В конце — **мини-бриф + сценарий + эффект**.

### 4.2. Дерево вопросов

**Уровень 0 — Контекст**
- `Q1` Отрасль? [логистика · производство · финансы · энергетика · фарма/химия · телеком · ИТ · другое]
- `Q2` Ваша роль? [бизнес-владелец · операции · R&D · ИТ · аналитик]

**Уровень 1 — Тип задачи (определяет архетип)**
- `Q3` Что по сути нужно сделать?
  - **A. Выбрать лучший вариант из множества комбинаций** (расписание, маршрут, распределение, портфель) → **ветка ОПТИМИЗАЦИЯ**
  - **B. Предсказать / классифицировать по данным** → **ветка ML/QML**
  - **C. Рассчитать свойства вещества / материала / молекулы** → **ветка СИМУЛЯЦИЯ**
  - **D. Оценить риск / перебрать множество сценариев (Монте-Карло)** → **ветка СЭМПЛИНГ**
  - **E. Не уверен** → показать 3–4 примера-картинки → отнести к ветке

**Ветка ОПТИМИЗАЦИЯ** (самая частая для near-term)
- `O1` Что именно оптимизируете? [расписание/смены · маршруты/логистика · распределение ресурсов · портфель · сеть · раскрой/упаковка · производственный план]
- `O2` Сколько объектов нужно расставить/назначить одновременно? [<50 · 50–500 · 500–5 000 · 5 000+] *(G1: комбинаторный взрыв)*
- `O3` Сколько ограничений и какие? [мало/много] · [есть жёсткие «нельзя нарушать»? да/нет] *(G2)*
- `O4` Как решаете сейчас и хватает ли? [вручную · Excel · эвристика · коммерческий солвер] + [времени/качества хватает? да/нет] *(G1)*
- `O5` Когда добавляете объекты — время решения растёт резко? [да · нет · не знаю] *(экспоненциальность)*
- `O6` Есть чёткая метрика «лучше»? [минимизировать стоимость/время · максимизировать прибыль/покрытие · несколько целей] *(G2)*
- `O7` Объём входных данных на задачу? [несколько параметров · таблицы · большие массивы] *(G3: I/O)*
- `O8` Как часто решаете? [разово · еженедельно · ежедневно · реальное время] *(ценность)*
- `O9` Сколько стоит текущее решение и цена ошибки? [вилки/диапазоны] *(ROI)*
- → **выход**: архетип «оптимизация», формулировка QUBO/CQM, подход «гибридный квантовый солвер»,
  референс-кейс по подтипу (см. библиотеку), вилка эффекта.

**Ветка СИМУЛЯЦИЯ**
- `S1` Что моделируете? [молекула · материал · катализатор · батарея · белок · физ.процесс]
- `S2` Классический метод (DFT/MD) не тянет по точности/размеру? [да · нет · не знаю]
- `S3` Размер системы (число атомов/электронов)? [малый · средний · большой]
- `S4` Что нужно на выходе? [энергия · свойства · ход реакции · новый дизайн]
- → **выход**: «естественный» квантовый кейс; горизонт чаще среднесрок/FT; референс Boeing/Mercedes/Covestro/Mitsubishi.

**Ветка СЭМПЛИНГ / риск**
- `R1` Что оцениваете? [риск портфеля · ценообразование деривативов · надёжность · общий Монте-Карло]
- `R2` Сколько сценариев/итераций и сколько это занимает сейчас? [диапазоны]
- → **выход**: amplitude estimation, потенциал квадратичного ускорения (пока research), референс Goldman/JPMorgan.

**Ветка ML/QML**
- `M1` Что предсказываете/классифицируете?
- `M2` Объём и структура данных? [небольшие/структурированные · большие массивы] *(G3 — риск I/O)*
- `M3` Классический ML уже работает? Чего не хватает?
- → **выход**: чаще **watchlist** (data-loading bottleneck) + честная оговорка; редкие структурированные кейсы — в PoC.

**Уровень 3 — Общий хвост (для всех веток)**
- `G_data` Готовность данных? [есть · частично · нет]
- `G_infra` Готовность ИТ/команды/бюджета? [да · частично · нет]
- `G_comp` Жёсткие ограничения (комплаенс/безопасность данных)? [да/какие · нет]

### 4.3. UX-приёмы (как у Акинатора)
- Один вопрос на экран, прогресс-бар, «не знаю» всегда доступен (не блокирует).
- Подсказки/примеры под каждым вариантом (как «lenses» у AWS — отраслевые формулировки).
- Живой индикатор «похоже на: оптимизацию расписаний» обновляется по ходу (вовлечение).

## 6. Формат выхода (что видит клиент)

1. **Вердикт пригодности:** `Перспективно → PoC` · `Watchlist` · `Классики достаточно` · `Не для кванта` —
   с короткой причиной (на каком фильтре/наблюдении основано).
2. **Сценарий решения:** «Ваша задача — это {подтип} ({архетип}); формализуется как {QUBO/Hamiltonian};
   подход — {квантовый/гибридный/классический} солвер; похоже на кейс {референс}».
3. **Оценка эффекта:** вилка по аналогии с референс-кейсом + явный дисклеймер «оценка, не гарантия».
4. **Что приложить и кого позвать:** список данных + роли для интервью (разд. 3).
5. **Next step:** кнопка «передать экспертам» → автособранный **бриф (PDF)** уходит в очередь экспертов /
   на консультацию (хэндофф, как «supported»-режим MS / partner-программа AWS).

## 7. Что отдать разработчикам (как реализовать в v1)
- **Модель данных профиля задачи** = поля брифа (разд. 2) как слоты; анкета и гайдед-бриф пишут в одни слоты.
- **Правила (rule-based)**: gate-фильтры = булевы условия; архетип = маппинг ответа `Q3`/веток;
  скоринг = взвешенная сумма (разд. 1.3); матрица = пороги по двум осям.
- **Контент-таблицы** (не код): дерево вопросов (разд. 4), библиотека сценариев/эффектов (разд. 5) —
  храним как конфиг/таблицы, чтобы менять без релиза (аналог AWS «lenses»).
- **Без реального запуска кванта в v1** — только классификация и сценарий. Прозрачный скоринг + дисклеймер.
- **Сбор обезличенных прохождений** → улучшение порогов и библиотеки сценариев (будущая база знаний).

> Связь с преимуществами Q-Scope: vendor-нейтральность (рекомендуем архетип/подход, не железо),
> self-service (анкета без брифа), язык бизнеса (вопросы «от общего к частному»), честность
> (watchlist + дисклеймер), мост к экспертам (автобриф на выходе).
