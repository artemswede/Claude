# Шаг 1e. Полная анкета с ответвлениями — на ВЫБОР вопросов владельцем

> 🟠 Показана полная (адаптивная) версия со всеми ветками. Отметьте, что оставить в MVP:
> поставьте `[x]` (оставить) / `[ ]` (убрать) у каждого вопроса. После выбора зафиксируем финальный набор.
> Язык — для клиента-собственника (металлургия, 40+, бизнес-образование), без квантового жаргона.

## Словарь «внутреннее → клиенту» (термины для пользователя)
| Внутри (движок) | Клиенту показываем |
|---|---|
| архетип | тип задачи |
| оптимизация | поиск лучшего варианта из множества |
| симуляция | расчёт свойств материалов/веществ |
| сэмплинг | оценка рисков и перебор сценариев |
| ML/QML | прогноз по данным |
| gate-фильтр / QUBO / I/O-bottleneck | (не показываем; «где обычные методы буксуют», «можно ли чётко поставить цель», «много ли данных на вход») |

## Вердикты (R1) — 4 раздельных, бизнес-ярлыки (можно переименовать)
| Движок | Ярлык клиенту | Цвет |
|---|---|---|
| PoC сейчас | **«Готово к пилоту — можно начинать»** | 🟢 зелёный |
| Watchlist | **«Перспективно, но рано»** | 🟡 жёлтый |
| Классический солвер | **«Достаточно обычных решений»** | ⚪ серый |
| Отбросить | **«Не для квантовых технологий»** | 🔴 красный |

> Монетизация: 🟢 = проекты, которые можно начинать пилотом и зарабатывать на них.

### Блок 1 · Тип задачи (определяет ветку)
- [ ] **Q3.** Что вы по сути хотите получить? *(карточки с примерами)* — `[ядро]`
  - A — найти лучший вариант из множества (расписания, маршруты, загрузка оборудования, **состав шихты/сплава**, распределение) → **ветка «Поиск лучшего варианта»**
  - B — рассчитать свойства материала/вещества (**новая марка стали, легирование, коррозия/стойкость**, катализатор, покрытие) → **ветка «Свойства материалов»**
  - C — оценить риск / перебрать сценарии (финансовый риск, надёжность оборудования, логистический риск) → **ветка «Риски и сценарии»**
  - D — предсказать по данным (спрос, качество/брак, цены, отказы) → **ветка «Прогноз по данным»**
  - E — не уверен → показать примеры и помочь выбрать

### Ветка A · «Поиск лучшего варианта»
- [ ] **A1.** Что именно оптимизируете? *(расписание смен / маршруты / загрузка оборудования / состав шихты / раскрой-упаковка / план производства)* — `[ядро: подтип+референс]`
- [ ] **A2.** Сколько объектов нужно учесть одновременно? *(число)* — `[ядро: G1+масштаб]`
- [ ] **A3.** Много ли ограничений и есть ли жёсткие «нельзя нарушать»? — `[ядро: формализуемость]`
- [ ] **A4.** Как решаете сейчас и хватает ли по времени/качеству? *(вручную/Excel · эвристика · коммерческий солвер · никак)* — `[ядро: где буксует классика]`
- [ ] **A5.** Когда задача растёт — время резко увеличивается? *(да/линейно/нет)* — `[ядро: сложность]`
- [ ] **A6.** Что считаете «лучшим результатом»? *(минимум затрат/времени · максимум выхода годного/прибыли)* — `[ядро: цель]`

### Ветка B · «Свойства материалов»  *(наиболее релевантна металлургии)*
- [ ] **B1.** Что моделируете? *(новый сплав/марка · легирующая добавка · коррозия/стойкость · катализатор · покрытие · батарея)* — `[ядро: подтип+референс]`
- [ ] **B2.** Сейчас считаете классически (DFT/CALPHAD/термодинамика) — хватает точности/масштаба? — `[ядро: где буксует классика]`
- [ ] **B3.** Размер системы (число элементов/атомов) — *мал / средний / большой* — `[ядро: масштаб/реализуемость]`
- [ ] **B4.** Что нужно на выходе? *(устойчивость/энергия · прогноз свойств · поиск состава · ход реакции)* — `[ядро: цель]`

### Ветка C · «Риски и сценарии»
- [ ] **C1.** Что оцениваете? *(финансовый риск · надёжность оборудования · запасы/логистика · ценообразование)* — `[ядро: подтип]`
- [ ] **C2.** Сколько сценариев/итераций считаете и сколько это занимает сейчас? *(число + время)* — `[ядро: масштаб/боль]`

### Ветка D · «Прогноз по данным»
- [ ] **D1.** Что предсказываете? *(спрос · качество/брак · цены · отказы)* — `[ядро: подтип]`
- [ ] **D2.** Объём данных — *небольшие таблицы / большие массивы* — `[ядро: много ли данных на вход]`
- [ ] **D3.** Обычные модели уже работают? Чего не хватает? — `[ядро: где буксует классика]`

### Блок 9 · Общий хвост (для всех веток)
- [ ] **T1.** Какие данные есть, их объём и насколько они чувствительны? — `[ядро: данные]`
- [ ] **T2.** Как часто решаете задачу? *(разово/периодически/ежедневно/реальное время)* — `[ядро: ценность]`
- [ ] **T3.** Сколько задача стоит сейчас / цена ошибки / ожидаемый эффект? *(диапазоны)* — `[ядро: бизнес-ценность]`
- [ ] **T4.** Готовность: данные / ИТ / команда / бюджет / комплаенс? — `[ядро: реализуемость]`
- [ ] **T5.** Допустимо ли «достаточно хорошее» решение вместо идеального? — `[опц.: уточняет потенциал]`
- [ ] **T6.** Насколько легко было описать задачу? *(1–5, CSAT)* — `[опц.: метрика]`

### Хэндофф

### Как считается вердикт (для справки, клиенту не показываем)
- **«Где буксует классика»** (A4/A5/B2/D3) → есть ли смысл в кванте.
- **«Чёткая цель + ограничения»** (A3/A6/B4) → можно ли формализовать.
- **«Много ли данных на вход»** (D2/T1) → не съест ли загрузка данных выигрыш.
- **Масштаб** (A2/B3/C2) + **бизнес-ценность** (T2/T3) + **готовность** (T4) → две оси → вердикт-цвет.

### Что выбрать (подсказка)
- **Минимальный набор (быстрый MVP):** Q1, Q3, одна ветка по архетипу (4–6 вопросов), T1–T4, H1 → ~10–12 вопросов.
- Уберёте ветки — анкета станет полностью статичной (короче, но грубее оценка).
