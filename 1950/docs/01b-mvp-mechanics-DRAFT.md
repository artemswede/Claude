
## 3. Система метрик (по решению владельца)
Делим по реализуемости в MVP (без интеграций, хостинг бесплатный).

### Реально в MVP (клиентские + анонимные счётчики)
| Метрика | Как считаем |
|---|---|
| **Completion Rate** | старт анкеты → экран результата |
| **Drop-off по шагам** | счётчик «дошёл до вопроса N» (выявить узкие места) |
| **Average Time to Complete** | таймстамп старт→финиш |
| **Распределение вердиктов / архетипов / отраслей** | агрегат по результатам |
| **Кол-во сгенерированных брифов** | счётчик «бриф готов» = квалиф. инициативы |
| **CSAT** | вопрос в конце 1–5: «насколько легко было описать задачу?» |

> ⚠️ Даже эти метрики и лид-капчер требуют **минимального хранилища** счётчиков/лидов. Предлагаю
> **Cloudflare KV** (бесплатный тариф) — это не «работа с пользовательскими данными», а анонимные
> счётчики + опц. контакт. **[РЕШИТЬ D6]:** KV для счётчиков/лидов — да/нет (по умолчанию — да).

### Требует стороны экспертов (ручной замер / пост-MVP)
- **Share of Qualified Leads** — доля брифов, взятых экспертами в работу.
- **False Positive Rate** — «перспективно» по системе, но эксперт отклонил.
- **Time Saved per Lead** — время эксперта на структурированный бриф vs неструктурированный запрос.
- **Expert Feedback** — «чего не хватает в брифах».
> В MVP закладываем место под эти данные (поле «вердикт эксперта» в брифе), но измеряем вручную.

## 4. Главная гипотеза MVP (формулировка владельца)
«Мы можем перевести задачу с языка бизнеса на язык физиков и автоматически отсеять нерелевантные запросы»
— успех = экономия времени экспертов и качество маршрутизации, а не продажи.
