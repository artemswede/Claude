## Анкета

**Q1. Отрасль** `[META]` — выбор: Логистика/транспорт · Производство · Финансы · Химия/материалы/фарма · Энергетика · Телеком · ИТ/другое.

**Q2. Ваша роль** `[META]` — выбор: Бизнес-владелец · Операции · R&D · ИТ/аналитик.

**Q3. Что по сути нужно сделать?** `[ARCH]` — выбор:
- A — выбрать лучший вариант из множества комбинаций (расписание, маршрут, распределение, портфель) → **Оптимизация**
- B — рассчитать свойства вещества/материала/молекулы → **Симуляция**
- C — оценить риск / перебрать множество сценариев (Монте-Карло) → **Сэмплинг**
- D — предсказать/классифицировать по данным → **ML/QML**
- E — не уверен → показать примеры; по умолчанию — наиболее вероятный для отрасли

**Q4. Как решаете сейчас и хватает ли?** `[G1][Y]` — выбор: Вручную/Excel · Эвристика/скрипт · Коммерческий солвер · Никак; и: устраивает по времени/качеству? Да / Частично / Нет.

**Q5. Сколько объектов/переменных в задаче одновременно?** `[G1][X]` — **число** (для симуляции — размер системы; «не знаю» допустимо).

**Q6. При росте объёма сложность/время растёт резко?** `[G1]` — выбор: Да, резко · Линейно · Нет/не знаю.

**Q7. Есть чёткая цель «что лучше» и понятные ограничения?** `[G2]` — выбор: Да — и цель, и ограничения · Только цель · Нет/размыто.

**Q8. Сколько данных нужно «загрузить» на вход задачи?** `[G3]` — выбор: Немного параметров · Таблицы среднего размера · Очень большие массивы.

**Q9. Частота решения** `[X]` — выбор: Разово · Периодически · Ежедневно · Реальное время.

**Q10. Годовая стоимость/потери от текущего решения** `[X]` — **число** (₽/$, «0/не знаю» допустимо).

**Q11. Допустимо ли «достаточно хорошее» (приближённое) решение?** `[Y]` — выбор: Да · Нет · Зависит.

**Q12. Готовность данных / ИТ / команды к пилоту** `[X]` — выбор: Высокая · Средняя · Низкая.

**Q13. CSAT** `[META]` — «Насколько легко было описать вашу задачу?» 1–5.

**Лид-капчер (опц.):** имя + e-mail (можно пропустить).

## Логика движка (детерминированная)

### Gate-фильтры (любое «нет» → не near-term квант)
- **G1 (классика провисает):** PASS, если `Q4=Не/Частично хватает` **и** (`Q6=Да, резко` **или** `Q5 ≥ порог_по_архетипу`).
- **G2 (формализуемость):** PASS, если `Q7 = Да — и цель, и ограничения` (для симуляции — допускаем «Только цель»).
- **G3 (нет I/O-bottleneck):** PASS, если `Q8 ≠ Очень большие массивы`; для архетипа ML «большие массивы» → FAIL.

### Архетип
Из Q3. `archetype_fit`: Симуляция = 5 · Оптимизация = 4 · Сэмплинг = 3 · ML/QML = 2.

### Оси (0–5)
- **Y (квантовый потенциал)** = f(`archetype_fit`, классическая твёрдость `Q4/Q5/Q6`, допустимость приближённого `Q11`).
- **X (бизнес-ценность/реализуемость)** = f(стоимость `Q10`, частота `Q9`, готовность `Q12`, горизонт по архетипу).

### Вердикт (квадрант)
- **Любой gate = FAIL:** если `X` высокий → **Классический/гибридный солвер**; если низкий → **Отбросить**.
- **Все gate = PASS:** `Y` высокий → далее по `X`: высокий → **PoC сейчас**; низкий → **Watchlist**.

## Выход: сценарий + эффект (из библиотеки)
По `(архетип + отрасль + подтип)` берём референс-кейс и вилку эффекта из библиотеки сценариев
(`data/competitors-and-spec-reference.md`, раздел «Библиотека сценариев…») и примеров `data/scenarios.csv`.
Формула текста: «Ваша задача — {подтип} ({архетип}); формализуется как QUBO/Hamiltonian; подход —
{квант/гибрид/классика}; похоже на кейс {референс}; ориентир эффекта — {вилка}. Это оценка, не гарантия.»
