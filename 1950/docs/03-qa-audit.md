# Шаг 3. Контроль качества — строгий аудит документации (Цикл 1)

> Роль: придирчивый аудитор. Цель — найти логические дыры и слабые места ДО заморозки (Шаг 4).
> Методология: 5–6 циклов «находки → правки → повторный аудит». Это **Цикл 1**.
> Объект аудита: `01`, `01b`, `01c`, `01d`, `01e`, `02`.

**Must-fix до заморозки:** A1, A2, A3, A4, A5, A6, A7, A8.

## CRITICAL

### A1 · Движок (`01c`) не соответствует финальной анкете (`01e`)
- **Где:** `01c` (пороги по Q1–Q13) vs `01e` (Q1–Q3 + ветки A/B/E + T1–T6 + H1).
- **Проблема:** правила движка ссылаются на `Q4…Q12` линейной анкеты, которой больше нет. Маппинг
  «вопрос → gate/ось» разъехался с реальными вопросами.
- **Почему дыра:** по `01c` невозможно однозначно посчитать вердикт для анкеты `01e` — это блокер для
  тестов (Шаг 5) и кода (Шаг 7).
- **Фикс:** переписать правила движка против ID из `01e` (A1–A6, B1–B4, T1–T5). Свести единую таблицу
  «вопрос → фактор».

### A2 · Ветка E «не уверен» не имеет решения в MVP (ИИ ушёл в v1.1)
- **Где:** `01e` (E1 — свободный текст) + D7 (ИИ → v1.1).
- **Проблема:** E1 опирался на ИИ для определения типа задачи; без ИИ в MVP ветка E «повисает».
- **Почему дыра:** часть пользователей выберет «не уверен» и упрётся в тупик.
- **Фикс (детерминированный):** заменить E на 2–3 простых уточняющих вопроса-картинки («вы скорее
  *ищете лучший вариант* или *считаете свойства материала*?») → маршрут в A или B. Свободный текст
  оставить как необязательный комментарий для брифа (без разбора ИИ).

## MAJOR

### A3 · Логика вердикта: «Отбросить» (🔴) почти недостижим + дыры на краях
- **Где:** `01c` блок «Вердикт».
- **Проблема:** 🔴 достижим только при `gate FAIL && X<3`. Случай «все gate PASS, но Y<3 и X<3»
  падает в Watchlist; нет правила для «слабо/слабо». Граница high/low ровно 3.0 — поведение на `=3`?
- **Фикс:** задать полную таблицу истинности (gates × X × Y) со всеми 4 исходами; зафиксировать `≥3 = high`;
  определить, когда «слабо/слабо» → 🔴, а когда → 🔵.

### A4 · `c_value`: пороги стоимости, валюта и «0/не знаю» не заданы
- **Где:** `01c` (`c_value`), `01e` (T3), `01` (Q10 «₽/$»).
- **Проблема:** «buckets по порядку величин» без чисел; валюта то ₽, то $; `0/не знаю` обнуляет ценность
  даже у важной задачи.
- **Почему дыра:** скоринг недетерминирован и зависит от валюты.
- **Фикс:** зафиксировать валюту (₽), задать диапазоны (например <1 млн=1 … >1 млрд=5); `не знаю` →
  нейтральные 2–3 балла, а не 0; в брифе пометить пробел.

### A5 · Обработка ответов «не знаю» в скоринге не определена
- **Где:** `01d` (CJM: «не знаю не блокирует»), `01c`, `01e`.
- **Проблема:** не сказано, как «не знаю» влияет на gate/ось. Много «не знаю» → произвольный вердикт.
- **Фикс:** правило: «не знаю» = нейтральный балл (середина), не меняет gate в одиночку; считать
  `confidence = доля заполненных`; при низком confidence — приписка «предварительно, нужны уточнения».

### A6 · Gate-фильтры заточены под оптимизацию; ветка B (материалы) недоопределена
- **Где:** `01c` (G1 «комбинаторный взрыв», G2 «QUBO»), `01e` (B1–B4).
- **Проблема:** для симуляции «классика провисает» = масштабирование DFT, «формализуемо» = гамильтониан,
  I/O почти неактуален. По B-вопросам gate не посчитать.
- **Фикс:** отдельный маппинг gate для ветки B: G1=`B2` (не хватает точности/масштаба), G2=`B4` (есть
  понятная цель расчёта), G3=न/п (PASS по умолчанию).

### A7 · Подтип → референс-кейс не перечислен для опций A1/B1
- **Где:** `01e` (списки A1/B1) vs библиотека сценариев (`data/...`, `01c`).
- **Проблема:** нет явной таблицы «опция анкеты → референс-кейс + вилка эффекта». Сервис не сможет
  выбрать сценарий детерминированно.
- **Фикс:** таблица соответствия для каждого пункта A1 и B1 → {референс, эффект, зрелость, горизонт};
  дефолт, если совпадения нет.

### A8 · Приватность/согласие/хранение для лид-капчера не определены (регуляторика «не знаю»)
- **Где:** `02` (LEADS в KV), `01e` (H1 e-mail), `01` (регуляторика не определена).
- **Проблема:** храним персональные данные (почту) без текста согласия, политики и срока хранения.
- **Почему дыра:** даже для демо это риск; «работы с данными не будет» противоречит хранению лидов.
- **Фикс:** явный чекбокс согласия + короткий текст приватности + срок хранения + возможность не
  оставлять контакт (бриф всё равно скачивается). Лиды — минимум полей.

## MINOR

### A9 · CJM-противоречия скоупу: «Отправить эксперту» и экран «Анализируем…»
- **Где:** `01d` (Шаг 4 loading; Шаг 6/7 «Отправить эксперту»).
- **Проблема:** «отправить эксперту» = доставка (интеграция), которой нет в MVP; движок <100 мс — экран
  «Анализируем…» был бы искусственной задержкой.
- **Фикс:** в MVP — «Скачать бриф» + лид-капчер (без реальной отправки); loading убрать или сделать
  мгновенным переходом.

### A10 · Главную гипотезу MVP нельзя проверить внутри MVP
- **Где:** `01b` (метрики качества требуют стороны экспертов).
- **Проблема:** «отсеиваем нерелевантное и экономим время экспертов» не подтвердить без ручной петли.
- **Фикс:** заложить лёгкую валидацию — ручной разбор экспертом N брифов после демо; в брифе — поле
  «вердикт эксперта».

### A11 · Бюджет записей KV для пошаговых событий
- **Где:** `02` (METRICS: `count:step:<n>` на каждый шаг).
- **Проблема:** free-tier KV ~1000 записей/день; пошаговые события быстро выберут лимит.
- **Фикс:** батчить — одна запись на завершении с массивом достигнутых шагов; либо считать только
  ключевые события (start/complete/verdict).

### A12 · Гигиена документов
- **Проблема:** `01c`/`01e` помечены «DRAFT/FULL», но являются согласованными; `01c` частично заменён
  `01e`; нумерация Q разная.
- **Фикс:** при заморозке — переименовать в чистые имена, в шапке указать «актуально/заменяет».

Приоритет правок: **A1 → A2 → A3 → A4 → A5 → A6 → A7 → A8** (логическое ядро и приватность), затем
