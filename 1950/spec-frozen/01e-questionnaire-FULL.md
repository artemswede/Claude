# Шаг 1e. Анкета MVP — ФИНАЛЬНЫЙ набор

> 🟢 Учтён выбор владельца: активны ветки **A, B, E**; ветки **C, D** показываются как «в разработке»
> (серые неактивные). Язык — простой, без сложных терминов. (Термин-образ «Акинатор» не используем.)

## Словарь «внутреннее → клиенту»
| Внутри (движок) | Клиенту показываем |
|---|---|
| архетип | тип задачи |
| оптимизация | поиск лучшего варианта из множества |
| симуляция | расчёт свойств материалов/веществ |
| gate-фильтр / QUBO / I/O | (не показываем; спрашиваем простыми словами: «где обычные методы буксуют», «можно ли чётко поставить цель», «много ли данных на вход») |

## Вердикты (4 цвета, клиент-ориентированные)
> Философия: ни один ответ не «бросает» клиента — у каждого есть следующий шаг (вход в нашу воронку проектов).

| Цвет | Ярлык клиенту | Что значит | Внутри |
|---|---|---|---|
| 🟢 | **«Можно начинать пилот»** | задача годится для кванта — запускаем проект (точка монетизации) | PoC сейчас |
| 🟡 | **«Перспективно — вернёмся позже»** | потенциал есть, но пока рано; держим на контроле | Watchlist |
| 🔵 | **«Есть классическое решение»** | квант не нужен, но мы решим обычными методами — помогаем | Классический солвер |
| 🔴 | **«Квант здесь не нужен»** | для этой задачи квантовые технологии не дают смысла | Отбросить |

## АНКЕТА (финальная)

### Блок 0 · Контекст
- **Q1.** Ваша отрасль *(список)*
- **Q2.** Ваша роль *(список)*

### Блок 1 · Тип задачи
- **Q3.** Что вы хотите получить? *(карточки)*
  - 🟢 **A — найти лучший вариант из множества** (расписания, маршруты, загрузка мощностей, распределение ресурсов, рецептура/состав) → ветка A
  - 🟢 **B — рассчитать свойства материала или вещества** (новый материал, сплав, покрытие, химия, катализатор, батарея) → ветка B
  - 🟢 **E — не уверен / опишу своими словами** → помощь с выбором
  - ⚫ **C — оценить риск и перебрать сценарии** — *в разработке* (серая неактивная кнопка)
  - ⚫ **D — спрогнозировать по данным** — *в разработке* (серая неактивная кнопка)

### Ветка A · «Поиск лучшего варианта»
- **A1.** Что именно оптимизируете? *(расписание · маршруты · загрузка оборудования · распределение ресурсов · рецептура/состав · план производства)*
- **A2.** Сколько объектов нужно учесть одновременно? *(число)*
- **A3.** Много ли ограничений и есть ли жёсткие «нельзя нарушать»?
- **A4.** Как решаете сейчас и хватает ли по времени/качеству? *(вручную/Excel · обычная программа · никак)*
- **A5.** Когда задача растёт — время резко увеличивается? *(да / понемногу / нет)*
- **A6.** Что считаете «лучшим результатом»? *(минимум затрат/времени · максимум выхода/прибыли)*

### Ветка B · «Свойства материалов»
- **B1.** Что моделируете? *(новый материал/сплав · добавка · стойкость/коррозия · катализатор · покрытие · батарея)*
- **B2.** Сейчас считаете обычными методами — хватает точности и масштаба?
- **B3.** Размер системы — *маленькая / средняя / большая*
- **B4.** Что нужно на выходе? *(устойчивость · прогноз свойств · поиск состава · ход реакции)*

### Ветка E · «Не уверен» (фикс A2 — без ИИ, детерминированно)
Два простых вопроса-картинки маршрутизируют в A или B (ИИ не нужен):
- **E1.** Что ближе к вашей задаче? *(две карточки)*
  - «Выбрать **лучший вариант** из множества (расписание, маршрут, загрузка, распределение)» → **ветка A**
  - «Понять **свойства материала/вещества** (прочность, состав, химия)» → **ветка B**
- **E2.** *(если всё ещё не ясно)* Что у вас на входе? *(«объекты и правила выбора» → A · «вещество/материал» → B)*
- **E3.** *(необязательно)* Опишите задачу своими словами — текст попадёт в бриф как комментарий
  (в MVP не разбирается; авторазбор ИИ — v1.1).

### Блок 9 · Общий хвост (для всех веток)
- **T1.** Какие данные есть, их объём и насколько они чувствительны?
- **T2.** Как часто решаете задачу? *(разово / периодически / ежедневно / постоянно)*
- **T3.** Сколько задача стоит сейчас / цена ошибки / ожидаемый эффект? *(диапазоны)*
- **T4.** Готовность: есть ли данные / ИТ / команда / бюджет?
- **T5.** *(пояснение)* **Вам нужен идеально точный ответ — или достаточно быстрого, близкого к лучшему?**
  Квантовые и ускоренные методы часто дают «почти идеальный» ответ быстро, а не строго идеальный. Вопрос
  выясняет, приемлемо ли это для вашей задачи. *(да, достаточно близкого / нужен только идеальный / зависит)*
- **T6.** *(в самом конце, наша обратная связь — не влияет на вердикт)* **Насколько легко было описать задачу? (1–5)**

### Хэндофф
- **H1.** Имя + рабочая почта + согласие *(только в конце, после результата)*

## AI-опция (ответ на вопрос владельца)
Да, прикрутить ИИ можно — и **не сложно для MVP**, если держать его тонким слоем, не ломая прозрачный движок:
- **Где полезнее всего:** ветка **E** — клиент пишет задачу словами, ИИ предлагает тип задачи и
  предзаполняет ответы. ИИ **только подсказывает**, вердикт всегда считает детерминированный движок.
- **Плюс:** ИИ может «причесать» текст вердикта и брифа в человеческий язык.
- **Как:** Cloudflare Workers AI (в той же платформе, без внешних интеграций, есть бесплатный лимит).
- **Риски:** +0.5–2 с к ответу, вариативность, лимиты free-tier.
- **D7 (решено):** ИИ — в **v1.1**. В MVP ветка E решается без ИИ (см. аудит, фикс по E-ветке).

## Как считается вердикт (для справки; клиенту не показываем)
«Где буксует классика» (A4/A5/B2) · «чёткая цель + ограничения» (A3/A6/B4) · «много ли данных» (T1) ·
масштаб (A2/B3) + ценность (T2/T3) + готовность (T4) + допустимость близкого (T5) → две оси → вердикт-цвет.
