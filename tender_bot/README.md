# Бот мониторинга тендеров на трубы большого диаметра (ТБД)

Telegram-бот, который через API агрегатора находит **проверенные** (завершённые,
с определённым победителем) закупки **труб большого диаметра** со всех площадок
и отдаёт по каждой: **цену, объём и победителя**.

Работает в двух режимах одновременно:
- **По запросу** — команда `/search` ищет свежие тендеры по фильтру ТБД.
- **Автоподписка** — `/subscribe`, и бот сам присылает новые тендеры по мере появления.

## Почему так устроено

Единого бесплатного API «по всем площадкам» в РФ не существует. Официальный
агрегатор всех закупок (44-ФЗ / 223-ФЗ) — **ЕИС / zakupki.gov.ru**, но он отдаёт
данные в виде XML по OpenData/FTP, что неудобно. Поэтому здесь используется
**платный агрегатор** (Контур.Закупки, Тендерплан, Seldon, Synapse и т.п.) с
удобным REST API.

Чтобы не привязываться к одному вендору, источник данных вынесен за абстракцию
`TenderProvider`. В комплекте:
- `MockProvider` — встроенные демо-данные, работает без ключа (для проверки бота);
- `AggregatorProvider` — настраиваемый адаптер под любой REST-агрегатор.

Вся бизнес-логика (определение ТБД, фильтр «только с победителем», цена/объём/
победитель, дедупликация рассылки) — общая и не зависит от источника.

## Структура

```
tender_bot/
├── bot/
│   ├── config.py            # конфигурация из переменных окружения
│   ├── models.py            # модель Tender (нормализованный тендер)
│   ├── filters.py           # логика фильтра ТБД + «проверенные»
│   ├── formatting.py        # рендер тендера в сообщение Telegram
│   ├── storage.py           # SQLite: подписки + дедупликация
│   ├── scheduler.py         # фоновый опрос и рассылка подписчикам
│   ├── main.py              # точка входа, сборка зависимостей
│   ├── handlers/commands.py # /start /help /search /subscribe /unsubscribe /status
│   └── providers/
│       ├── base.py          # абстракция TenderProvider
│       ├── mock.py          # демо-данные без ключа
│       └── aggregator.py    # адаптер под платный REST-агрегатор
├── tests/                   # pytest
├── run.py                   # запуск с авто-загрузкой .env
├── requirements.txt
└── .env.example
```

## Быстрый старт (без ключа, демо-данные)

```bash
cd tender_bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите BOT_TOKEN от @BotFather, PROVIDER оставьте mock

python run.py
```

В Telegram: `/start`, затем `/search` — увидите демо-тендеры на ТБД с ценой,
объёмом и победителем. `/subscribe` включит автоуведомления.

## Подключение реального агрегатора

1. Получите API-ключ у выбранного агрегатора (Контур.Закупки / Тендерплан / Seldon).
2. В `.env`:

   ```ini
   PROVIDER=aggregator
   AGGREGATOR_BASE_URL=https://api.ваш-агрегатор.ru/v1
   AGGREGATOR_API_KEY=ваш-ключ
   AGGREGATOR_SEARCH_PATH=/search
   AGGREGATOR_AUTH_HEADER=Authorization
   AGGREGATOR_AUTH_SCHEME=Bearer
   ```

3. Подгоните маппинг полей под формат ответа вашего агрегатора в
   `bot/providers/aggregator.py` — словари `DEFAULT_FIELD_MAP` (где в JSON лежат
   `winner`, `startPrice`, `volume` и т.д.), `REQUEST_PARAM_MAP` (имена query-
   параметров) и `RESULTS_PATH` (путь к массиву записей). Менять логику не нужно —
   только пути в JSON.

   Если у вашего агрегатора принципиально другой протокол (GraphQL, SOAP,
   многошаговый), отнаследуйтесь от `AggregatorProvider` и переопределите
   `_build_request` / `_parse_response`.

## Что считается «проверенным тендером»

`Tender.is_verified == True`, когда статус закупки = `COMPLETED` (итоги подведены)
**и** есть победитель. По умолчанию `ONLY_WITH_WINNER=true`, поэтому бот не
показывает идущие/несостоявшиеся торги.

## Что считается ТБД

Тендер проходит фильтр, если его ОКПД2 в семействе стальных труб (`24.20…`)
**или** наименование содержит ключевые слова, **и** при этом похоже на большой
диаметр: явное «большого диаметра»/«ТБД» либо диаметр ≥ 530 мм в названии
(530, 720, 820, 1020, 1220, 1420 …). Это отсекает мелкие трубы (отопление,
водоснабжение). Настраивается через `OKPD2_PREFIXES` и `KEYWORDS`.

## Развёртывание

Бот работает на long polling — отдельный публичный адрес не нужен. Запускайте
`python run.py` под systemd / в Docker / на любом VPS. Для постоянной работы
держите процесс под супервизором (systemd, supervisor, docker restart=always).
SQLite-файл (`DATABASE_PATH`) хранит подписки — не удаляйте его между перезапусками.
